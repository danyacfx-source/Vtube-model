# Проверки режима живой камеры

Среда: Chromium в Linux, WebGL через SwiftShader; Python 3; все ресурсы приложения раздаются локально.

Проверены:

- Загрузка обеих 3D-моделей и трёх лицевых сеток. До включения камеры синтетические лица скрыты.
- MediaPipe Face Mesh обнаружил 468 точек на тестовом портрете. Три живые видеотекстуры отображаются на модели.
- Текстуры глаз/рта визуально проверены после исправления UV-проекции в системе координат отображаемой модели.
- Переключение апельсина/ананаса, режим вывода, возврат по Esc.
- Отрицательный тест: чёрный кадр не даёт лица, старые фрагменты скрываются.
- Запуск через `getUserMedia` с виртуальной камерой Chromium: лицо найдено, фрагменты отображаются.
- Во время работы камера переключает персонажа без перезапуска видеопотока.
- «Остановить»: все видеотреки переходят в `ended`, `video.srcObject` очищается, лицевые сетки скрываются.
- Повторное включение после остановки успешно.
- Аудиотреки не запрашиваются.
- В перечисленных сценариях нет ошибок JavaScript и запросов за пределы локального адреса, blob/data ресурсов.

Тестовые исходные фото/видео не включены в приложение. Для проверки использовался публичный тестовый портрет `astronaut.png` из scikit-image; тестовые скриншоты с этим лицом не опубликованы.

Повторный запуск тестов (Playwright и Chromium — только зависимости разработки, пользователю приложения не требуются):

```sh
python live-face/serve.py --no-browser
python tools/test_live_face.py --image /path/to/face.png
python tools/test_live_camera.py --camera /path/to/face-video.y4m
```

Не проверено в этой среде: физическая веб-камера пользователя, Windows BAT-файл, захват в OBS, фактическая производительность на пользовательском компьютере. Виртуальная камера и тестовый кадр не заменяют проверку этих пунктов.
